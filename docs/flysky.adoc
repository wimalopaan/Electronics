This project is a replacement-firmware for the FySky FS-I6S transmitter. 

It is completely written from scratch in _Rust_. It has far more features that the original FlySky transmitter firmware (like <<oix6>>), 
but has a complete different design compared to e.g <<oix6>>.

You'll find some videos about the hardware-modifications and the firmware itself on my https://www.youtube.com/@wilhelmmeier6124/videos[YouTube]-Channel.

=== Hardware-Modifications

This firmware allows the same hardware modifications as <<oix6>>, but also some more modifications.

* replace SWA...SWD with 2pos/3pos switches or potentiometers
* add two additional digital-only switches SWE / SWF
* add up to four analog input (potentiometers) VRC...VRF
* add an external rf-module either full- or haalf-duplex
* add a positve / negative-polarity power-switch for the external rf-module

Because this handset does not have enough physical buttons, but does have a touch-controller, the UI operation 
is a mix of touch-gestures and the two buttons on the back of the handset.

You'll find some videos about the hardware-modifications and the firmware itself on my https://www.youtube.com/@wilhelmmeier6124/videos[YouTube]-Channel.

=== Hardware-Modifications

This firmware allows the same hardware modifications as <<oix6>>, but also some more modifications.

* replace SWA...SWD with 2pos/3pos switches or potentiometers
* add up to five analog input (potentiometers or 2pos/3pos/6pos switches) VRC...VRG
* add two 2pos switches SG and SH (in addition to the SE/SF on the back of the handset) 
* add an external CRSF rf-module either full- or half-duplex
* add a positve / negative-polarity power-switch for the external rf-module

[[i6s-cpp]]
== i6s-cpp: a C++26 port of the FlySky-I6X-rs / FlySky-I6S-rs firmware

[caption=""]
.Project info
[cols="1h,5",width="100%"]
|===
| Status | 🟡 experimental
| Firmware | https://github.com/wimalopaan/i6s-cpp[wimalopaan/i6s-cpp] (AGPL-3.0)
| Configuration | Menus on the handset, CRSF module parameter browser, USB CDC command line
| See also | <<flysky-i6x-rs>>, <<flysky-i6s-rs>>, <<building.adoc#,Building firmware>>
|===

This project ports the _Rust_ firmware <<flysky-i6x-rs>> and <<flysky-i6s-rs>> to _modern C++_ (C++26).
One code base serves both handsets; the board is selected at compile time.

[WARNING]
--
The firmware is not verified on hardware yet. The pin and timer assignments come from the Rust source and are not
yet checked against the schematic.
--

[[i6s-cpp-design]]
=== Design

* CMSIS only (no HAL)
* `constexpr` / `consteval` wherever possible
* static polymorphism only (no virtual functions), no heap, no exceptions, no RTTI
* pure logic (`src/wm/logic/`, `src/wm/util/`) is separated from the hardware drivers (`src/wm/hw/`) and is tested on the host
* target: STM32F072 (Cortex-M0), built with clang and `-Oz`

[[i6s-cpp-features]]
=== Features

All parts of the Rust firmware are ported:

* RF: AFHDS 2A (A7105) and an external CRSF module (full- or half-duplex), including the CRSF parameter menu for the module
* mixer, dual rate / expo, throttle curve, wing mixer, aux channels, trims, calibration, safety / preflight checks
* telemetry (AFHDS 2A and CRSF), vario, flight timer, dashboard pages P1 to P5
* model memory with A/B slots in the I2C EEPROM, model copy, migration of older EEPROM layouts
* USB: HID gamepad (simulator mode) and CDC serial (command line, telemetry)
* trainer port (PPM)
* FS-i6S: power latch, touch navigation (FT6236), rear pots VRA/VRB as jog wheels, rear buttons, SG/SH, VRC..VRG

The hardware modifications are the same as for the Rust firmware: see <<_hardware_modifications,FS-i6X>>
and <<_hardware_modifications_2,FS-i6S>>.

[[i6s-cpp-deviations]]
=== Differences from the Rust firmware

* CRSF: the telemetry tiles VSPD and ALT show CRSF data instead of AFHDS 2A data.
* FS-i6S: SE/SF availability follows the function of the rear buttons; timer and mix switches accept all switch
  conditions up to SWM.
* Some small differences in the Rust user interface are not ported (row order of Protocol/Vario, "Audio Test" row
  in the vario setup).

The complete list is in the https://github.com/wimalopaan/i6s-cpp#known-deviations-from-rust[README] of the repository.

[[i6s-cpp-build]]
=== Building

You need CMake (>= 3.20), clang with C++26 support and the `arm-none-eabi-gcc` toolchain (for the libraries).

----
cmake -S . -B build-fw -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi-clang.cmake -DCMAKE_BUILD_TYPE=MinSizeRel -DPCB=I6X
cmake --build build-fw
----

[cols="1m,3",options="header"]
|===
| Option | Meaning
| PCB=I6X | FlySky FS-i6X (default), output `i6x_fw.hex`
| PCB=I6S | FlySky FS-i6S, output `i6s_fw.hex`
| USE_USB=OFF | leave out the USB device stack to save flash (default `ON`)
|===

Host tests for the logic part:

----
cmake -S . -B build-host -DCMAKE_CXX_COMPILER=clang++ -DPCB=I6X
cmake --build build-host --target host_logic_tests
./build-host/host_logic_tests
----

=== Since Version `1.13`

Because of problems with the half-duplex solution and `CRSF_UNINVERTED`, this option was removed and the option `CRSF_FULLDUPLEX`
was introduced. As the name states, with this option it is possible to use a full-duplex, uninverted (normal) serial connection to the RX-as-TX.

All you have to do is to locate the `TX2` and the `PA15` pad on the mainboard of the `I6X`, refer to https://github.com/OpenI6X/opentx/wiki/Modifications#all-optional-hardware-connections[I6X elrs]
Connect the `rx`-pin of the RX-as-TX with the `TX2` pad on the board and the `tx`-pin of the RX-as-TX with the `PA15` pad on the board.
Then compile the firmware with the following options:

.cmake for uninverted full-duplex `crsf` on the `TX2` and `PA15` pad of the I6X mainbard.
[source]
--
$ cmake -DCRSF_FULLDUPLEX=YES -DEXTPWR_INVERT=YES -DUSB_SERIAL=OFF -DCMAKE_BUILD_TYPE=Release -DSPLASH=OFF  -DTIMERS=1 -DHELI=OFF -DTRANSLATIONS=DE -DPCB=I6X 
-DLUA_COMPILER=NO -DLUA=NO -DGVARS=YES  -DMULTIMODULE=OFF -DOVERRIDE_CHANNEL_FUNCTION=OFF -DPCBI6X_ELRS=YES -DPCBI6X_HELLO=YES ..
--

The option `EXTPWR_INVERT` inverts the logic on the `PC13` pad, that is used as a power-on signal to an external module. Normally the is _logic-high_ 
to signal power-on. If you want to used a simple P-channel MosFet at power-switch for the RX-as-TX, this mus be logic-low as power-on 
to the gate of the P-Channel MosFet. Be sure to use a MosFet with a low (<=2V) `Ugs` gate-source-threshold voltage 
(I use the https://www.digikey.de/de/products/detail/microchip-technology/LP0701N3-G/4902364?s=N4IgjCBcpgTAnBaIDGUBmBDANgZwKYA0IA9lANogAsYAzAOwAMVIAusQA4AuUIAylwBOASwB2AcxABfKcVgUQ2DoyYRWUoA[LP0701N3] in
a TO-92 package)

=== Before Version `1.13`

(be aware, that for some reason with this modification one get 5-8% packet loss on the connection handset <-> rx-as-tx)

All you need is to identify the `TX2` pad on the mainboard of the `I6X`, 
refer to https://github.com/OpenI6X/opentx/wiki/Modifications#all-optional-hardware-connections[I6X elrs]. This is used as the `S.Port` 
signal, which would be inverted. But fortunately there is a compile-time option to the firmare (`CRSF_UNINVERTED`) that can be set.
So the `cmake` line should be read as follows:

.cmake for uninverted `crsf` on the `tx2` pin of the I6X mainbard.
[source]
--
$ cmake -DCRSF_UNINVERTED=YES -DUSB_SERIAL=OFF -DCMAKE_BUILD_TYPE=Release -DSPLASH=OFF  -DTIMERS=1 -DHELI=OFF -DTRANSLATIONS=DE -DPCB=I6X 
-DLUA_COMPILER=NO -DLUA=NO -DGVARS=YES  -DMULTIMODULE=OFF -DOVERRIDE_CHANNEL_FUNCTION=OFF -DPCBI6X_ELRS=YES -DPCBI6X_HELLO=YES ..
--

The next dificulty is to get the regulated `5V` for the rx-as-tx. You can install a _LDO_ but it turns out to be sufficient to power the 
rx-as-tx with the internal `3.3V` of the https://github.com/OpenI6X/opentx/wiki/Modifications#all-optional-hardware-connections[mainboard].

If you want to power-off the external module, you can use `PC13` of the µC to control a power-switch for the module. If you are stouthearted desolder the
volatge-regulator from the ELRS-receiver (tx-module) and try to solder a p-Channel mosfet with _source_ and _drain_ on the same foorprint. Then use _PC13_ 
to drive the gate (by an additional n-Channel (to invert the polarity)) or use the `-DEXTPWR_INVERT=YES` compile-time switch.

=== Firmware

The https://github.com/OpenI6X/opentx[OpenI6X] project provides OpenTx for
small radios of the type _FlySky_ *FS-i6x*. 

=== Compiling

The following setup configures the firmware to include the following notable options:

[horizontal]
CRSF_FULLDUPLEX:: enables full-duplex communication with an ELRS module
CRSF_EXTENDED_TYPES:: enables decoding `float` and `string` CRSF types
EXTPWR_INVERT:: invert the level of the external power pin to use a p-channel Mosfet
TRANSLATIONS:: select german translation
PCBI6X_ELRS:: enable the internal ELRS _script_

[source]
--
cmake -DCROSSFIRE=YES -DCRSF_FULLDUPLEX=YES -DCRSF_EXTENDED_TYPES=YES -DUSB_MSD=OFF -DEXTPWR_INVERT=YES -DSBUS_TRAINER=OFF -DUSB_SERIAL=OFF -DCMAKE_BUILD_TYPE=Release -DSPLASH=OFF  -DTIMERS=1 -DHELI=OFF -DTRANSLATIONS=DE -DPCB=I6X -DLUA_COMPILER=NO -DLUA=NO -DGVARS=YES  -DMULTIMODULE=OFF -DOVERRIDE_CHANNEL_FUNCTION=OFF -DPCBI6X_ELRS=YES -DPCBI6X_HELLO=YES ..
--

If you like to use `gitpod.io` to compile the firmware (s.a. <<building.adoc#edgetx_custom,Custom EdgeTx builds>> and <<building.adoc#gitpod_wm,Compiling the source code of my projects (`wmucpp`)>>) 
use the following URI in your browser (prepend the URL https://github.com/wimalopaan/opentx[] with `https://gitpod.io/#`) 
https://gitpod.io/#https://github.com/wimalopaan/opentx[].

After a few minutes you see a `vscode` like UI with a terminal in the lower third of the workspace.
Copy the above `cmake` line to the terminal and hit `enter`.

Then type in the command: `make firmware`

After finishing you can download the file `firmware.bin` and do the normal flashing to your radio.
